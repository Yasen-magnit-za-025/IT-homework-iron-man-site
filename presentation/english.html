The three files sit in the same folder and depend on each other. sait.html is the entry point: its head links sait.css with a link tag and loads sait.js with a deferred script tag, plus a fonts folder for the Stark typeface. CSS is the biggest file because every section has its own look, a responsive version and motion rules. JavaScript is written as many small functions that each own one feature, so any one of them can be read on its own.

Viewport and title

Lines 4–10 set the character set, phone scaling, the tab title, a description and an arc‑reactor favicon drawn as inline SVG.

No referrer

The wiki that hosts the images blocks requests from other sites, so line 7 tells the browser to send no referrer at all.

Linking the files

Lines 11–20 preload fonts, link sait.css, flag that JS is running, then load sait.js with defer so it runs after the page is built.

5 / 44

Line 1 declares a modern HTML document. Line 2 opens the html element with the English language and a no-js class. Lines 4 and 5 set UTF-8 text and make phones use their real width instead of zooming out. Line 7 is the no-referrer rule: the image host refuses requests that say which site they came from. Lines 12 to 14 open early connections to Google Fonts and the image host so they load faster. Line 15 loads the Exo 2 font. Line 16 links the stylesheet. Line 17 is a one-line script that swaps no-js for "js is-booting": CSS uses that to hide things only when JavaScript is available, and to show the boot screen. 17 / 44

Part 2 defines the pieces every section shares. .eyebrow is the small label with a boxed number. .display is the huge section heading, and .display em is the outlined second word, done with a transparent fill and -webkit-text-stroke. .section-head lays out a heading block. .btn is the cut-corner button made with clip-path, with hover and pressed states; .round-btn is the circular arrow button; .chips and .chip are the round fact badges in the hero. Then comes the reveal system: anything with data-reveal starts hidden, shifted down and blurred, but only when the html element has the js class. Variants: "left" and "right" slide in sideways, "wipe" uncovers with clip-path, and "mask" slides text up from behind an overflow:hidden edge. When JavaScript adds is-in, every variant transitions to its final, normal state. --d is a delay set by JavaScript to stagger groups.

Part 3 builds the arc reactor from a single element and no images. The element is a circle with a radial gradient for the glowing centre and a box-shadow for the outer glow. ::before is the ring of copper coil segments: a repeating-conic-gradient masked into a ring and spun slowly. ::after is the bright core, pulsing with the "core" keyframes. The i element inside is the dashed inner ring, spinning the other way. Every size is calculated from --s, so the same class works at 26px in the nav, 74px on the boot screen and over 200px in the tech section. The boot screen is a full-screen overlay with the reactor, text and a loading bar. function initScrollLoop(updaters) {
  let ticking = false;
  const run = () => {
    const y = window.scrollY;
    updaters.forEach((fn) => fn && fn(y));
    ticking = false;
  };
  window.addEventListener('scroll', () => {
    if (!ticking) { ticking = true;
      requestAnimationFrame(run); } });
}

Scroll events can fire many times per frame. The ticking flag makes all the updates run at most once per screen refresh.

RECAP

Four ideas hold the whole site together

Tokens

Colours, fonts and curves live once in :root and are reused through var().

Classes and variables

JavaScript sets a class or a --variable; CSS does the drawing and animating.

One scroll loop

Every scroll scene is an update(y) run together, once per frame.

Safe by default

Without JS nothing hides; with reduced motion nothing moves; every control works by keyboard.

44 / 44

If you remember four things: first, design tokens (CSS variables on :root) make the look consistent and easy to change. Second, the split of responsibilities: HTML holds content, CSS holds looks and animation, and JavaScript mostly just flips classes and sets CSS variables. Third, all scroll effects share one requestAnimationFrame loop, and the pinned scenes all use the same recipe of progress, phase() windows and variables. Fourth, the site degrades gracefully: hidden states only apply when the js class is present, reduced-motion visitors get a still page, and the tabs, dialog, sliders and buttons are real, labelled controls that work with a keyboard and screen reader.
