Сърцето: един цикъл на кадър

function initScrollLoop(updaters) {
  let ticking = false;
  const run = () => {
    const y = window.scrollY;
    updaters.forEach((fn) => fn && fn(y));
    ticking = false;
  };
  window.addEventListener('scroll', () => {
    if (!ticking) { ticking = true;
      requestAnimationFrame(run); } });
}

Защо един цикъл

Събитията за скрол идват много пъти за един кадър. Флагът ticking пуска всички обновявания най-много веднъж на опресняване.

requestAnimationFrame

Изпълнява работата точно преди браузърът да рисува, така че всяка сцена при скрол се движи плавно и синхронно.

Наклон и „нагоре“

Плакатите се накланят към мишката с --rx и --ry; бутонът в ъгъла се появява след 1,2 екрана скрол.

initTilt (само с мишка, без намалено движение) следи курсора над всеки плакат с data-tilt и задава --ry и --rx за 3D наклон плюс --gx и --gy за позицията на отблясъка; излизането нулира наклона. initToTop връща update, която показва бутона „нагоре“ след 1,2 височини на екрана. initScrollLoop е ядрото на системата за движение. Всяка сцена при скрол му подава функция update(y). При скрол (маркиран като passive, така че браузърът никога не го чака) и при преоразмеряване тя заявява един анимационен кадър, освен ако вече има чакащ; в този кадър прочита scrollY веднъж и извиква всяка update. Така десетина ефекта при скрол не слушат и не прерисуват поотделно, което би накъсвало. Изпълнява се и веднъж веднага, така че всичко започва в правилното състояние. fancyPointer е true само при мишка и без намалено движение.
