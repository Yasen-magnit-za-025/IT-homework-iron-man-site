One span per letter

Each heading’s text is split into word spans (so lines still wrap between words) holding one span per letter.

A state per letter

Letters switch from off to scan to lock, staggered left to right; CSS draws each state.

Still readable

The split letters are hidden from screen readers; the heading keeps its full text in aria-label or a hidden copy.

initHudText (skipped for reduced motion) has two halves. split() walks the text inside a heading, replaces each text node with word spans (white-space nowrap, so words never break in the middle) containing one hud-ch span per character, all marked aria-hidden. The original text goes into the heading’s aria-label, or into a hidden .sr-only copy for plain paragraphs, where aria-label is ignored. decode() then runs a frame loop: each letter starts after i × a short step, spends 280ms in "scan" with a new random glyph (data-g) every 45ms, then becomes "lock". Headings decode once when 40% visible; the villain and tech panel headings re-decode every time their tab is shown, using a MutationObserver that watches the hidden attribute. The second half marks paragraphs as hud-print and adds is-printed when their container scrolls in, staggering paragraphs that share a container.
