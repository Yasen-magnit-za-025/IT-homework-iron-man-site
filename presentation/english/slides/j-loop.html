LINES 864–906 · POSTER TILT, BACK TO TOP, THE SCROLL LOOP

The heart of it: one loop per frame

function initScrollLoop(updaters) {
  let ticking = false;
  const run = () => {
    const y = window.scrollY;
    updaters.forEach((fn) => fn && fn(y));
    ticking = false;
  };
  window.addEventListener('scroll', () => {
    if (!ticking) { ticking = true;
      requestAnimationFrame(run); } });
}

Why one loop

Scroll events can fire many times per frame. The ticking flag makes all the updates run at most once per screen refresh.

requestAnimationFrame

Runs the work right before the browser draws, so every scroll scene moves smoothly and in sync.

Tilt and back to top

Posters tilt toward the mouse with --rx and --ry; the corner button appears after 1.2 screens of scrolling.

initTilt (mouse only, no reduced motion) tracks the pointer over each data-tilt poster and sets --ry and --rx for a 3D tilt plus --gx and --gy for the glare position; leaving resets the tilt. initToTop returns an update that shows the back-to-top button after 1.2 screen heights. initScrollLoop is the core of the motion system. Every scroll scene hands it an update(y) function. On scroll (marked passive, so the browser never waits for it) and on resize, it requests one animation frame unless one is already pending; in that frame it reads scrollY once and calls every update. This keeps a dozen scroll effects from each listening and redrawing separately, which would stutter. It also runs once immediately so everything starts in the right state. fancyPointer is true only with a mouse and no reduced motion.
